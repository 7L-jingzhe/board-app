# 需求规格说明书

> 文档编号：01
> 适用版本：Board App v1.0
> 状态：与实现同步（2026-11-27）
> 最后更新：2026-11-27

## 1. 背景与目标

现有 `lv_port_linux-release-v9.2` 是一个能交叉编译到 aarch64 开发板的 LVGL Linux 示例工程，已具备 framebuffer 显示与触摸输入的基础代码。本项目的目标是在不改动 LVGL 本体、不破坏原工程可编译性的前提下，新增一个结构清晰、可维护、可演示的板端应用集合：

- **好看**：1024×600 上保持简约、留白、统一的视觉语言。
- **好用**：入口清楚，点击/滑动/返回逻辑一致，任何页面都知道“怎么回去”。
- **好维护**：UI 与核心逻辑物理分离；核心可在 PC 上跑单元测试；新增应用有固定模板。
- **可交付**：在 WSL 的 ext4 目录中交叉编译通过，产出可部署到板子的 `main` 与资源目录。

本项目首先是一套**教学/课程设计级**的完整工程，其次才是功能演示。因此文档、目录规范、许可证说明与测试步骤是交付物的一部分。

## 2. 目标平台与前提假设

| 项目 | 假设 | 备注 |
|---|---|---|
| CPU / 系统 | aarch64 Linux | 顶层 CMake 使用 `aarch64-linux-gnu-gcc` |
| 显示 | 1024×600，32bpp framebuffer `/dev/fb0` | 现有 `lv_conf.h` 使用 `LV_USE_LINUX_FBDEV` |
| 触摸 | 单点触摸 `/dev/input/event6` | 现有 `main.c` 固定该节点；部署时可用环境变量覆盖（实现阶段补充） |
| 网络 | 可选，能访问 HTTP 天气接口 | 无网络时进入缓存/演示模式，不阻塞 UI |
| 存储 | 运行目录可写，能创建 `data/` | 用于缓存、设置、编辑后的图片、最高分 |
| 内存 | 至少 128 MB 可用 | LVGL 堆建议 4 MB；图片缓冲区按需分配 |
| 构建机 | WSL Ubuntu-26.04，CMake ≥ 3.16，aarch64 交叉编译器 | 编译必须在 WSL ext4 中进行，避免 `/mnt/d` 的 9p 性能损失 |

如果实际板子的分辨率、触摸节点或 framebuffer 不同，只需要改 `main.c` 的初始化和 `lv_conf.h` 的驱动配置；应用层全部使用相对布局，不写死 1024×600 之外的硬件细节。

## 3. 范围

### 3.1 本期包含

1. 主界面（Home）与统一导航。
2. 天气查询：当前天气、7 天预报、城市切换、刷新、缓存、离线兜底。
3. 相册：目录扫描、缩略图网格、大图查看、图片编辑（旋转/翻转/灰度/亮度/对比度/裁剪）、另存为 PNG、撤销/重置。
4. 小游戏中心：2048、贪吃蛇、打砖块；游戏规则核心来自开源项目；每个游戏有开始、暂停、继续、重开、结算、最高分。
5. 统一主题、字体、图标、弹窗、Toast、加载/空/错误状态。
6. CMake 构建、WSL 同步脚本、主机单元测试、板上部署说明。
7. 文档：需求、架构、UI、接口、构建、测试、维护、许可证。

### 3.2 本期不包含

- 用户登录、账号、云同步。
- 天气 API Key 管理、HTTPS/TLS 支持（本期只支持 HTTP 数据源；可通过替换 provider 扩展）。
- 相册的 EXIF 方向校正、滤镜预设、图层、文字贴纸、多选批量处理。
- 游戏联网对战、排行榜上传、音效/音乐（可后续扩展）。
- OTA 升级、看门狗、开机自启服务化。
- 多语言切换（本期中文 + 英文数字/符号）。
- 在 WSL 中直接运行 aarch64 程序（无 qemu；以交叉编译 + 主机核心测试 + 板上点检验证）。

## 4. 用户与典型场景

| 角色 | 场景 |
|---|---|
| 演示者 | 上电后看到主界面，依次点开天气、相册、游戏，展示完整交互 |
| 开发者 | 在 WSL 改代码、编译、拷贝到板子；通过日志定位问题 |
| 维护者 | 按模板新增一个应用或替换天气数据源，不需要读懂全部 UI 代码 |
| 评审者 | 按验收清单逐项操作，确认功能、视觉、稳定性、许可证合规 |

典型流程：

1. 上电 → 主界面显示时间/日期和三个应用卡片。
2. 点“天气” → 显示上次缓存（若有）并自动刷新 → 成功后展示当前天气与 7 天预报；失败显示错误与重试。
3. 返回 → 点“相册” → 网格浏览 → 点一张图 → 旋转/调亮度/裁剪 → 保存 → Toast 提示保存路径。
4. 返回 → 点“小游戏” → 选 2048/贪吃蛇/打砖块 → 玩一局 → 暂停/继续 → 结算 → 返回游戏中心。
5. 任意应用点左上角“返回”回到上一级；从主界面进入应用后，返回链为“应用 → 主界面”。

## 6. 非功能需求

| 类别 | 指标 | 说明 |
|---|---|---|
| 启动 | 上电到主界面 ≤ 3 s | 不含内核启动；资源扫描异步/延迟 |
| 帧率 | 常规页面 ≥ 30 FPS；打砖块 ≥ 50 FPS | 1024×600，32bpp；以板上实测为准 |
| 触摸延迟 | 按下到视觉反馈 ≤ 100 ms | 不做阻塞式网络/解码 |
| 内存 | LVGL 堆 ≤ 4 MB；图片缓冲峰值 ≤ 24 MB | 编辑图上限 1280×800；缩略图分级 |
| 网络 | 连接/读取超时 ≤ 6 s；失败可恢复 | 不因网络失败卡死 UI |
| 稳定性 | 连续进出应用 20 次无崩溃、无明显泄漏 | 对象数/内存回归 |
| 可维护性 | 新增一个应用 ≤ 5 个文件 + 1 处注册 | 模板化 |
| 可扩展性 | 新增应用只改 `app/` 下新文件夹，不改首页/导航/CMake 源列表 | CMake 自动 glob + 链接段自动注册 |
| 可测试性 | 核心逻辑可在 x86_64 主机编译运行 | 不依赖 LVGL/显示 |
| 可移植性 | UI 不写死绝对坐标/分辨率之外的硬件 | 以 1024×600 为基准，布局用 flex/grid/百分比 |
| 许可证 | 仅使用 MIT/BSD/Apache-2.0/OFL/Public Domain | 不引入 GPL 代码到本工程 |
| 编码 | C99，`-Wall -Wextra` 无新增警告 | 核心库更严格 |

## 7. 验收标准（演示脚本）

评审时按以下脚本完整走一遍，全部通过即视为 v1.0 验收：

1. **冷启动**：上电/启动程序，3 秒内出现主界面；时间与系统时间一致。
2. **主界面**：5 张卡片（聊天室/AI 聊天/天气/相册/小游戏）均可点击；按下有反馈；右上角账号胶囊可进入账户页。
3. **天气-在线**：显示北京当前天气与 7 天预报；点刷新出现加载态并更新；切换上海后城市与数据变化；返回再进入，城市仍为上海。
4. **天气-离线**：断网/改错地址后刷新，6 秒内进入错误态或显示缓存并标注“离线数据”；点重试不崩溃；返回主界面正常。
5. **相册**：进入后看到 ≥ 6 张示例图；滚动流畅；点开一张；旋转两次、灰度、调亮度、裁剪 1:1；撤销一次；保存；返回网格看到新图或提示保存路径。
6. **相册-空态**：把图片目录指向空目录后进入，显示空状态与路径提示，不崩溃。
7. **游戏中心**：4 张卡片（围棋/2048/贪吃蛇/打砖块）均显示最高分并一行放得下；分别进入各游戏。
8. **2048**：滑动合并得分；达到 2048 显示胜利弹窗；继续/重开；退出后最高分保留。
9. **贪吃蛇**：转向、吃食物、撞墙结束；暂停/继续；重开；退出后最高分保留。

## 8. 约束、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 板子无网络 / 接口被墙 | 天气不可用 | 缓存 + 演示数据 + 错误态；provider 可替换 |
| 第三方天气接口变更/停服 | 解析失败 | 版本化解析、字段缺失容错、Mock 兜底、文档说明替换点 |
| 板子内存较小 | 大图编辑 OOM | 编辑分辨率上限、缩略图分级、失败提示、可配置上限 |
| 字体子集缺字 | 显示方框 | 静态 UI 字形全量纳入；TinyTTF 设置 SimSun 16 兜底；提供字形生成脚本 |
| 原有工程 `ui/`/`src/` 残留 | CMake 冲突/重复入口 | 新工程独立目录；顶层只保留 `board_app` 入口；旧目录不参与构建并在文档标注 |
| WSL `/mnt/d` 编译慢 | 构建时间不可接受 | 源码 rsync 到 ext4 后编译；构建目录也在 ext4 |
| 无板子可运行 | 无法自动验证 UI | 主机核心单测 + 交叉编译 + 板上点检清单；后续可加 headless 截图工具 |
