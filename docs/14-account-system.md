# 系统账户（全系统统一登录）

> 文档编号：14
> 状态：与实现同步（2026-11-27），重启自动登录验证通过
> 入口：首页顶栏右上角账号胶囊（显示「未登录」或当前用户名）

## 1. 为什么要把账户从聊天室里独立出来

原来聊天室自带登录页，围棋要另登一次。问题很实际：

- 同名账号第二次登录会被服务器踢下线（服务器按名字认人）；
- 两个应用各持一条 TCP 连接、各自的在线表，好友状态会不一致；
- 账户本质是**系统级资源**（身份、好友、连接），不该属于某个业务页面。

现在的结构：

```text
board_ui/ui_comm_session  ── 单例：一条连接 + 登录态 + 好友缓存 + 事件多播
        ▲            ▲              ▲
   app/account   app/comm      app/games/weiqi
   （登录/好友）  （聊天室）      （联网围棋）
```

- `comm_session_init()` 幂等，首次调用创建队列、客户端与事件泵；
- 页面只 `subscribe/unsubscribe`，**不销毁连接**；
- 好友列表缓存在会话里，聊天室和围棋直接读；
- 页面没打开时收到的对局邀请会暂存一次（`comm_session_take_pending_invite`）；
- **私聊/群聊在会话层就直接写聊天记录**（`comm_history_append`），不依赖页面。

涉及的文件：

| 文件 | 作用 |
|---|---|
| `ui/include/board_ui/ui_comm_session.h` + `ui/src/ui_comm_session.c` | 会话单例（连接/登录态/好友缓存/事件多播/自动登录/记住账号） |
| `app/account/ui/account_ui.c` | 账户页（登录/注册/好友管理/退出登录） |
| `main_page/home_ui.c` | 首页顶栏账号胶囊（每秒刷新） |
| `app/comm/core/src/comm_history.c` | 聊天记录持久化（session 调用） |
| `board_app.c` | 启动时 `comm_session_init(&s_paths)` + 1.5 s 后自动登录 |

## 2. 账户页

- **未登录**：服务器地址（默认空，占位提示格式；记住上次的）、用户名、密码 + 登录/注册，
  底部英文键盘（点输入框自动绑定）；
- **已登录**：当前账号、好友列表（在线状态、可删除）、加好友、退出登录。

登录成功后会记住账号，并写入本地配置。

## 3. 记住账号 + 开机自动登录

### 3.1 存储

`data/settings.conf`（`board_storage`）：

| 键 | 说明 |
|---|---|
| `comm.user` | 用户名 |
| `comm.pass` | 口令的**本地弱混淆**串（不是明文，也不是加密） |
| `comm.host` | 登录成功后记住的服务器地址 `IP:端口`（首次没有，需要手填） |
| `comm.remember` | `1` 表示记住了 |

> 说明：板子是本机单用户设备，要让「开机自动登录」就必须能在本地取回口令。
> 这里用 `0x5A + i*7` 的逐字节异或再转十六进制，**只是避免明文躺在配置文件里**，
> 不提供真正的机密性。要更高的安全性需要服务器签发长期 token（未实现）。

### 3.2 启动流程

```text
board_app_init()
  └─ comm_session_init()            创建会话
  └─ lv_timer(1500ms, 只跑一次) ──> comm_session_auto_login()
                                        ├─ 优先读环境变量 BOARD_APP_COMM_AUTOLOGIN
                                        └─ 否则用 comm.user/comm.pass/comm.host
```

延迟 1.5 秒是为了**不拖慢首屏**：服务器没开时连接会等超时，用户先看到首页更舒服。
登录成功后首页顶栏的账号胶囊在 1 秒内自动变成用户名 + 绿点。

**服务器地址不写死在代码里**：登录页默认是空的（占位提示给个格式示例），
首次由用户自己填 `IP:端口`，登录成功后连同账号一起记住；如果本地没有
`comm.host`，就**不会**尝试自动登录（不猜地址）。服务器自己的监听端口是固定的
`20000`（可用 `--port` 改），这一点按需求保持写死。

### 3.3 退出登录

点「退出登录」会 `comm_session_logout()`：断开连接、清空 `comm.pass`
并写 `comm.remember=0`。用户名保留在配置里，下次打开账户页仍会预填，
但**不再自动登录**（退出就是退出）。

### 3.4 环境变量（演示/看板）

```bash
BOARD_APP_COMM_AUTOLOGIN="127.0.0.1:20000,alice,alice123" ./main
```

优先级高于本地记住的账号，且登录成功后同样会被记住。

## 4. 各页面的行为

| 页面 | 未登录时 | 已登录时 |
|---|---|---|
| 首页 | 顶栏显示「未登录」+ 灰点 | 显示用户名 + 绿点 |
| 账户 | 登录/注册表单 | 账号 + 好友管理 + 退出登录 |
| 聊天室 | 「还没有登录账号」+「去登录」按钮 | 直接进好友列表与聊天 |
| 联网围棋 | 「需要先登录账号」+「去账户登录」 | 大厅里选好友邀请对局 |

## 5. 验证

```text
# 1) 显式登录一次（模拟用户操作）
[comm] autologin as alice -> 127.0.0.1:20000
$ cat data/settings.conf
comm.user=alice
comm.pass=3b0d010c134cb6b8      <- 混淆串，不是明文 alice123
comm.remember=1

# 2) 重启（不带任何环境变量）
[comm] 发现上次登录的账号 alice，尝试自动登录
[comm] autologin as alice -> 127.0.0.1:20000
首页顶栏 => alice ●（绿点）
```

`kill -9` 与 `kill -TERM` 两种退出方式都验证过，凭据都不会丢。

## 6. 顺带修复

- **`board_storage_get_str()` 返回共享缓冲区**：连续取两个键会互相覆盖，
  导致把密码串当成用户名去登录。现在统一先 `storage_copy()` 拷走再取下个键。
- **小游戏列表挤出屏幕**：4 款游戏时卡片宽度从 304 自适应到 222（一行放得下），
  宽度变化时内部元素按比例重排，打砖块不再被挤到屏幕外。
